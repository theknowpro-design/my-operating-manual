# My Operating Manual - PDF Engine Documentation

## Architecture Overview

The PDF Engine is a **locked, single-purpose module** that generates Operating Manual PDFs exclusively. It cannot be extended, modified, or used for other PDF types.

```
Input (Markdown)
    ↓
    ├─→ [1] Schema Validation
    │     ✗ Check for Money Maker content
    │     ✗ Validate brand/logo options
    │
    ├─→ [2] Asset Whitelist Check
    │     ✓ Logo URL must be whitelisted
    │     ✗ Reject non-approved assets
    │
    ├─→ [3] Version Metadata Load
    │     ✓ Read version.json
    │     ✓ Generate timestamp
    │
    ├─→ [4] HTML Processing
    │     ✓ Markdown → HTML conversion (marked)
    │     ✓ HTML injection with version comments
    │
    ├─→ [5] PDF Generation
    │     ✓ HTML → Canvas (html2canvas)
    │     ✓ Canvas → PDF (jsPDF)
    │     ✓ Inject PDF metadata
    │
    └─→ [6] File Export
          ✓ Generate filename
          ✓ Trigger browser download
          ✓ Return result
```

## Entry Point

### generateOperatingManualPdf(markdown, options)

**LOCKED:** This is the only function exported from the PDF Engine.

#### Signature

```javascript
export async function generateOperatingManualPdf(
  markdownOrHtml = '',
  options = {}
) → Promise<object|undefined>
```

#### Parameters

**`markdownOrHtml` (string, required)**
- Operating Manual markdown or HTML
- Cannot be empty
- Cannot contain Money Maker terminology
- Example: `"# Jordan's Operating Manual\n\n## 1. Identity & Role\n\nI'm a..."`

**`options` (object, optional)**
```javascript
{
  // PERMISSIBLE OPTIONS (can customize)
  title: string,           // PDF title, defaults to "My Operating Manual"
  subtitle: string,        // PDF subtitle, defaults to "Personal Operating Manual"
  author: string,          // Author name, defaults to "My Operating Manual"
  generatedAt: Date|string,// Generation timestamp, defaults to now()
  filename: string,        // Output filename, auto-generated if omitted
  
  // LOCKED OPTIONS (cannot customize)
  // brand: 'My Operating Manual' (hardcoded, no override)
  // logoUrl: Teal Read Me Logo (hardcoded, no override)
  
  // METADATA (optional)
  metadata: {
    title: string,
    description: string,
    keywords: string[],
    // ... custom metadata ...
  }
}
```

#### Return Value

**Success:**
```javascript
{
  success: true,
  blob: Blob,              // PDF file blob
  filename: string,        // Generated filename
  size: number,            // File size in bytes
}
```

**Failure:** Throws error with code (see Error Codes section)

#### Usage Example

```javascript
import { generateOperatingManualPdf } from './modules/pdf-engine/exportManager.js'

try {
  const result = await generateOperatingManualPdf(
    '# Jordan\'s Operating Manual\n\n## 1. Identity & Role\n\nI\'m a product lead...',
    {
      title: 'Jordan\'s Operating Manual',
      author: 'Jordan',
      generatedAt: new Date(),
    }
  )
  console.log('PDF generated:', result.filename, result.size)
} catch (error) {
  console.error('PDF generation failed:', error.code, error.message)
}
```

## Validation Layers

### Layer 1: Schema Validation

**What:** Enforces Operating Manual content rules

**Checks:**
- ✓ Content is non-empty string
- ✗ Content is not Money Maker terminology (profit engine, niche graph, income potential, etc.)
- ✗ Brand option is not "My Operating Manual" (locked)
- ✗ Logo option is not "Teal Read Me Logo.png" (locked)

**Error Code:** `OPERATING_MANUAL_SCHEMA_VIOLATION`

**Enforced by:** `modules/pdf-engine/validators/inputSchema.js`

### Layer 2: Asset Whitelist Validation

**What:** Ensures only approved logos/assets are used

**Whitelisted Assets:**
- `Teal Read Me Logo.png` ✓
- Any other asset ✗

**Check:**
```javascript
const assetValidation = validatePdfAsset(brandingConfig.logo);
if (!assetValidation.valid) {
  throw new Error(`[PDF Assets] ${assetValidation.reason}`);
}
```

**Error Code:** `ASSET_WHITELIST_VIOLATION`

**Enforced by:** `modules/pdf-engine/validators/assetWhitelist.js`

### Layer 3: Markdown to HTML

**What:** Safely converts markdown to HTML

**Process:**
1. Check if input looks like HTML (starts with `<`)
2. If markdown: convert with `marked.parse()` with `gfm: true`
3. If HTML: use as-is
4. Wrap in light-mode container with version comments

**Output:**
```html
<!-- Generated by My Operating Manual v1.0.0 -->
<!-- Build: 2026-08-12T05:10:00Z -->
<!-- App Version: 1.0.0 -->
<article class="operating-manual-pdf" data-theme="light" style="color:#2a2f3a;background:#ffffff;">
  <!-- converted markdown or input HTML -->
</article>
```

## Version Metadata Injection

### Version System

Every PDF includes comprehensive version information for tracking and debugging.

**Version File:** `modules/pdf-engine/version.json`

```json
{
  "pdfEngineVersion": "1.0.0",
  "pipelineVersion": "1.0.0",
  "appVersion": "1.0.0",
  "buildTimestamp": "2026-08-12T05:10:00Z",
  "systemName": "My Operating Manual",
  "description": "Operating Manual PDF generation system - locked architecture for single-purpose PDF exports"
}
```

### Injection Points

**1. HTML Comments**
```html
<!-- Generated by My Operating Manual v1.0.0 -->
<!-- Build: 2026-08-12T05:10:00Z -->
<!-- App Version: 1.0.0 -->
```
Visible in browser dev tools and HTML source.

**2. PDF Metadata**
```javascript
metadata: {
  appVersion: '1.0.0',
  pdfEngineVersion: '1.0.0',
  generatedAtUtc: '2026-08-12T05:10:00Z',
  // ... other metadata ...
}
```
Visible in PDF properties (File → Properties → Custom).

**3. Generated Timestamp**
- Real-time generation when PDF is created
- Added to metadata: `generatedAtUtc`
- Different from build timestamp

### Version Propagation

```
modules/pdf-engine/version.json (source of truth)
    ↓
getVersionWithTimestamp() (read + add timestamp)
    ↓
formatVersionHtmlComment() (create HTML comments)
    ↓
generateOperatingManualPdf() (inject into PDF)
    ↓
PDF includes both build version and generation time
```

## Branding (Locked)

### Branding Configuration

**File:** `modules/pdf-engine/brandingConfig.js`

```javascript
import logo from './assets/Teal Read Me Logo.png?url'

export const brandingConfig = {
  logo,                           // Resolved logo URL
  logoFile: 'assets/Teal Read Me Logo.png',
  logoPlacement: 'top-center',
  logoWidth: 120,
  coverLogoWidth: 120,
  accentColor: '#008080',         // Teal
  footerText: 'Generated by My Operating Manual',
  includeLogoOnCover: true,
  includeLogoOnFooter: false,
}
```

### Cannot Override

The following are hardcoded in `generateOperatingManualPdf()`:

```javascript
// LOCKED BRAND: Cannot be overridden
brand: 'My Operating Manual',
author: options.author || 'My Operating Manual',

// LOCKED LOGO: Only Teal Read Me Logo is allowed (whitelisted)
logoUrl: brandingConfig.logo,  // Always use configured logo, never override
includeLogo: options.includeLogo !== false,
```

### Why Locked?

1. **Single Purpose** — All PDFs must be clearly marked as My Operating Manual
2. **Brand Consistency** — No confusion with other systems (especially Money Maker)
3. **Asset Hygiene** — Prevents legacy logo injection
4. **Architecture Integrity** — Forced consistency supports the locked design

## PDF Generation Pipeline

### HTML to Canvas to PDF

**Library:** `html2canvas` + `jsPDF`

**Process:**

1. **HTML Canvas Rendering**
   ```javascript
   const canvas = await html2canvas(htmlElement, {
     scale: 2,
     backgroundColor: '#ffffff',
     logging: false,
   })
   ```

2. **PDF Creation**
   ```javascript
   const pdf = new jsPDF({
     orientation: 'portrait',
     unit: 'mm',
     format: 'a4',
   })
   ```

3. **Canvas to PDF**
   ```javascript
   pdf.addImage(canvas, 'PNG', 0, 0, width, height)
   ```

4. **Metadata Injection**
   ```javascript
   pdf.setProperties({
     title: options.title,
     author: options.author,
     subject: options.subtitle,
     keywords: metadata.keywords,
   })
   ```

5. **File Export**
   ```javascript
   pdf.save(filename)
   ```

## Error Codes

| Code | Message | Recovery | Trigger |
|------|---------|----------|---------|
| `OPERATING_MANUAL_SCHEMA_VIOLATION` | Schema validation failed | No | Input validation |
| `ASSET_WHITELIST_VIOLATION` | Asset not on whitelist | No | Logo validation |
| `PDF_GENERATION_ERROR` | PDF generation failed | Yes | html2canvas or jsPDF error |
| `FILE_EXPORT_ERROR` | File download failed | Yes | Download trigger |

## Filename Generation

### buildPdfFilename(title)

Generates safe, filesystem-friendly filenames.

**Process:**
1. Sanitize title (remove special characters)
2. Add timestamp (YYYY-MM-DD)
3. Add file extension (.pdf)

**Examples:**
- Input: `"Jordan's Operating Manual"` → Output: `"Jordan's Operating Manual 2026-08-12.pdf"`
- Input: `"My Operating Manual"` → Output: `"My Operating Manual 2026-08-12.pdf"`
- Input: `"A/B Test (2026)"` → Output: `"AB Test 2026 2026-08-12.pdf"`

## Limitations & Constraints

1. **Single Content Type** — Only Operating Manual content accepted
2. **Fixed Branding** — Cannot customize logo or brand name
3. **No Extensibility** — Cannot add new validation rules or rendering options
4. **Client-Side Only** — No server-side processing
5. **No Streaming** — Entire PDF generated before download
6. **No Persistence** — No storage, export only
7. **Browser Dependent** — Requires modern browser with Canvas API

## Performance Notes

- **Generation Time** — Usually <2 seconds
- **File Size** — Typically 100-500 KB per PDF
- **Memory** — One canvas in memory during generation
- **Network** — No network calls during generation

## Future Proofing

To keep the PDF Engine locked and consistent:
